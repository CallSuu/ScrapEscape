## 보존·실행 안내

개인 게임용 scrap_escape DB는 이번 검증에서 변경하지 않았다. 다음 정상 서버 시작 시 Flyway가 해당 DB에 새 스키마를 적용한다. 초기 버전 게임은 데이터와 조합법을 보존해 조회만 허용하며 새 게임은 rulesVersion2로 생성한다. 기존 schema.sql·data.sql 내용은 V1 마이그레이션으로 옮겼다.

IntelliJ에서 Gradle을 새로 불러오고 기존 서버를 중지한 다음 ScrapEscapeApplication을 재실행한다. 치료 POST /api/games/{id}/treatments, 탈출 POST /api/games/{id}/escape를 사용한다.

## 구현 선택과 남은 검증

- 동일 장소 후보를 상대 가중치1로 균등 추첨한다. 수량2개 이상이면 서로 다른2종류로 나누며 수량 분배는 균등 추첨한다. 공간 부족 시 먼저 추첨된 종류를 우선 보관한다.
- 폭풍 간격은 시작 시각 간24~48시간으로 확정했고1~3시간 지속하므로 겹치지 않는다.
- 의료 키트는 예방 사용 가능하며 치료가 기한에 닿으면 시간은 진행하고 실패한다. 실패 시 키트로 회복시키지 않는다.
- 프론트엔드·아이콘 만료 색상·게임 배경·모달·비밀의 방은 미구현이다. 비밀의 방은 MVP 밖이다.
- 실제 탈출률·플레이 길이·여러 재료 세척에 필요한 세척액 공급 밸런스는 미검증이다. 화면 연동 후 조정해야 한다.
- Boot 관리 Flyway가 MySQL9.6은 자체 검증 범위보다 새 버전이라는 경고를 표시하지만 이번 fresh/legacy/재시작 검증은 통과했다.
