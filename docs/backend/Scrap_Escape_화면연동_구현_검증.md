# 화면 조회·미리보기·공통 통신 구현 검증

기준일2026-10-27. [화면 연동 명세](../frontend/Scrap_Escape_화면_연동_명세.md) · [API 명세](../api/Scrap_Escape_API_명세서.md)

## 변경

- SE-16 GET screen: State·탐색 카드·안전지대 미리보기. 읽기 전용 트랜잭션. DTO7개 추가, 기존 응답/변경 경로 호환 유지. DB 마이그레이션 없음(V6 유지).
- 휴식·세척·폐기·이동·수리·치료·탈출의 실행 제한과 예상값. 기한은 실패 경고/실행 허용, 두 기한 중 TIME_LIMIT 우선 유지.
- Spring Boot 정적 ES module game-api.mjs: UUID 요청·중복 클릭 차단·정확한 본문/번호 재사용·수동 재시도·최신 screen 갱신·버튼 제한 helper. 새 프레임워크나 라이브러리 없음.

## 검증

- 새 화면 경로가 없을 때11개 통합 테스트가404로 실패(RED). 구현 후 전체 MySQL115개 통과: 실패0·오류0·건너뜀0. bootJar 성공.
- 화면 검증: 읽기 무변경/즉시 기회 보존, 휴식 회복 상한·오염 감소, 기한 우선, 치료 기한 도달·정상 치료,48h 세척 대상 보호/타 재료 만료, 가득 찬 상자 CLEAN 병합/미세척 이동 차단, 자원 부족·폐기, 수리 조건·예상 완료, 종료/이전 판, 탈출/없는 판.
- JS11개 통과: 응답 유실·원래 본문/UUID 보존, 중복 클릭, 성공 후 갱신 실패의 GET만 재시도,409 오류/새 번호/가용 상태 자동 재조회,500 재시도,잘못된JSON,15초 제한을 짧게 설정한 타임아웃,새 게임/다음 행동,GET 오류,버튼 disabled/이유.
- 실제 JAR18080포트·scrap_escape_test에서 SE-16 초기·기한/만료·종료 상태 응답3개 수집. 치료 미리보기8개 필드가 실제 치료 후 값과 일치했다.
- `/js/game-api.mjs`가 text/javascript로 제공되는 것을 확인했다. 실제 공통 JS 모듈로 POST 새 게임→GET screen→POST6h휴식→GET screen 성공.6h만 진행·미확인 요청 없음 확인. 최종 JAR에서 미수리 탈출409 이후 screen 자동 갱신과 제공 모듈/소스 일치도 확인.
- Controller16개작업·OpenAPI36개 스키마·실제 JSON 예시30개·참조/로컬 문서 링크 확인.
- 독립 코드 검토에서 조치할 정확성 문제 없음. 개인 scrap_escape DB는 변경하지 않았고 이번 검증용 판만 삭제했다. 검증 서버 종료.

## 남은 검증

실제 메인 화면/HUD/선택창은 아직 만들지 않았다. DOM 배치·이미지·반응형 겹침·키보드/스크린리더·실제 브라우저 클릭/네트워크 UI 검증은 화면 구현 단계에서 수행한다. 페이지 새로고침 후 요청 맥락 복원·이어하기는 현재 범위가 아니다. 종료 요약 보존/순위표는 GAP-04 결정 후, 밸런스는 완성 후 플레이로 검토한다.
