# Scrap Escape — 비밀의 방 백엔드 구현·검증

검증일: 2026-10-26 (Asia/Seoul)

## 구현 내용

- 일반 탐색마다 열쇠10%·해당 장소 미발견 방15% 독립 판정. 빈손 탐색에도 적용하며 종료된 탐색은 새 열쇠·방을 지급하지 않는다.
- 열쇠는 별도 최대2개이며 실제 저장한 수량만 획득 통계로 집계한다.
- 방은6개 장소마다1개·한 번 개방. 발견 시 기억하고 자동 입장하지 않는다.
- 발견한 장소에만 secretRoom 정보를 반환하며 버튼 문구는 ? 하나다. 열쇠·체력이 없어도 정보 조회는 가능하다.
- 즉시 입장은1시간·체력1·열쇠1. 다른 유효 행동·지나치기로 기회가 끝나며 GET·실패 요청은 기회를 소모하지 않는다.
- 기억한 방 재방문은 낮4시간·체력2,밤5시간·체력3. 질병이면 각각+2. 이동·개방 포함이며 추가 비용 없음.
- 좋은 결과80%(재료3~4개50%,세척액2회분 또는 키트1개30%),나쁜 결과20%(미세척 인벤토리 재료1~2개 손실10%,오염+15가10%).
- 손실은 입장 시점의 미세척 인벤토리만 대상으로 하며 없으면 오염+15로 대체한다. 보관함·세척 완료·사용 불가 재료는 보호한다.
- 방문 시간의 폭풍·질병·재료 만료·실패 기한을 반영한다. 재방문은 연속 탐색에 포함하지만 일반 탐색 보상을 중복 지급하지 않는다.
- 보상 재료는 완료 시각의 별도 미세척 묶음. 공간 초과분 안내와 보급품 한도를 적용한다.
- 게임·장소 복합 PK와 게임 행 잠금·트랜잭션으로 열쇠·보상·손실·개방·통계를 함께 반영한다.
- 결과 통계는 state.secrets.statistics에 방 발견·개방·미개방,열쇠 획득·사용,좋은·나쁜 결과,추가 재료·손실을 제공한다. 남은 열쇠는 state.secrets.keyAmount.

## API

| 메서드 | 경로 | 기능 |
|---|---|---|
| GET | /api/games/{id}/secret-rooms | 발견한 방 목록 |
| GET | /api/games/{id}/secret-rooms/{locationId} | 입장 비용·제한 이유·과거 결과 |
| POST | /api/games/{id}/secret-rooms/{locationId}/open | mode=IMMEDIATE 또는 REVISIT로 입장 |
| POST | /api/games/{id}/secret-rooms/{locationId}/defer | 미개방 방 선택창 닫기·지나치기 |

프론트엔드는 방이 미발견이면 ? 버튼을 숨기고, 발견한 방의 ?는 정보창만 연다. 실제 입장 버튼은 preview.allowed로 제어한다. 미개방 선택창 X는 defer를 요청하고, 이미 개방한 결과창 X는 화면만 닫는다.

## DB 보존과 실행

V1~V4는 수정하지 않고 V5만 추가했다. 기존 판은 초기화하지 않으며 열쇠0과 아직 발견하지 않은 방 상태로 시작한다. 개인 게임용 scrap_escape DB는 이번 검증에서 변경하지 않았고,정상 서버 재시작 시 Flyway가 V5를 적용한다.

IntelliJ에서 Gradle 동기화 후 기존 서버를 중지하고 ScrapEscapeApplication을 다시 실행한다. 비밀의 방은 새 UI 없이 API로만 사용할 수 있다.

## 남은 작업

프론트엔드·? 버튼·정보창·이미지·실제 한 판의 플레이 길이 및 난이도 조정은 아직 미구현/미검증이다. 비밀의 방 백엔드는 사용자 요청에 따라 MVP 이후 선택 확장 범위까지 구현했다. 배포·GitHub push는 수행하지 않았다.
