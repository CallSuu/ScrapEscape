# 탐색 보상·비밀의 방 화면 학습 가이드

## 현재 구현한 흐름

메인 → 탐색 지역 선택 → 탐색하기 → **탐색 결과 전체 화면** → 확인 → 메인.

새 비밀의 방을 발견했다면 확인 다음에 **비밀의 방 선택 전체 화면**이 나온다. 들어간다 → 방 결과 전체 화면 → 확인 → 메인. 나중에 들어간다 → 위치를 기억하고 메인. 두 선택은 열쇠가 있어야 활성화된다. 열쇠가 없으면 회색으로 표시되며, 상단 메인으로 돌아가기로 나갈 수 있다. 나중 선택과 돌아가기는 열쇠를 소비하지 않는다. 즉시 기회는 종료되고 이후 ?에서 재방문할 수 있다.

## 파일과 역할

- `src/main/resources/static/js/app.mjs`: 화면 이동·서버 통신·재시도·확인 명령을 관리한다.
- `src/main/resources/static/js/exploration-result.mjs`와 `css/exploration-result.css`: 큰 보상 아이콘·수량·확인 버튼을 만든다.
- `src/main/resources/static/js/secret-room.mjs`와 `css/secret-room.css`: 열쇠·비용·오염·입장/나중 선택을 표시한다.
- `src/main/resources/static/js/main.mjs`: 항상 표시하는 HUD와 지역 배경을 바꾼다.
- `src/main/resources/static/assets/locations/location-N.svg`: 장소별 임시 그림이다. 추후 실제 디자인으로 교체할 수 있다. 재료도 현재는 임시 기호/이모지 아이콘이다.

## 화면 이동과 DB 변화 구분

| 사용자 행동 | 요청·데이터 변화 |
|---|---|
| 탐색하기 | 기존 POST explorations → 서버가 시간·체력·재료·발견 처리 → GET screen으로 HUD 갱신 |
| 보상 확인 | 로컬 ACK_EXPLORATION_RESULT. POST 없음, 재료 중복 지급 없음 |
| 방 정보 읽기 | 최신 screen의 비용과 상태 표시. 열쇠 소비 없음 |
| 들어간다 | 기존 POST secret-rooms/{locationId}/open → 열쇠1개 소비 및 방 처리 → GET screen |
| 나중에 들어간다 | 기존 POST defer → 즉시 기회 종료·위치 기억 유지. 시간/체력/열쇠 소비 없음 |
| 돌아가기 | 기본 로컬 이동. 발견 직후 방이면 호스트가 defer를 한 번 처리 |

보상 타일에는 생성 수량(quantity)이 아니라 **실제로 담은 수량(collectedQuantity)**을 사용한다. 공간이 부족해 남긴 재료는 별도 문구로 표시한다. 세척액·키트·열쇠도 실제 추가량만 타일로 표시한다. 빈손은 정상 탐색이며 비용이 소모된다. 보급품 한도가 찼으면 보상을 받은 것처럼 표시하지 않는다.

실패로 끝난 탐색도 보상 화면을 먼저 보여주고 확인 후 최종 결과 화면으로 연결한다. 최종 통계 화면과 안전지대 제품 모듈은 팀원 B의 별도 작업이며 현재 연결 준비 안내가 표시된다.

재시도는 기존 요청 번호와 응답을 유지한다. 처리 성공 후 GET만 실패했다면 GET만 재시도한다. 진행 중 돌아간 화면은 늦은 응답이 와도 다시 열지 않는다. 이때 최신 HUD와 전역 메시지로 결과를 확인한다.
