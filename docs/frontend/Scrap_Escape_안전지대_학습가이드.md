# 안전지대·최종 결과 화면 학습 가이드

현재 운영 배치는 숲속 야영지의 공간별 진입으로 변경됐다. 아래 관리 기능/API는 유지되며 이전3열 전체 보기는 독립 개발 페이지에서 제공한다. [현재 화면 안내](Scrap_Escape_야영지_화면_학습가이드.md).

## 이제 할 수 있는 것

메인에서 **안전지대**를 누르면 상태·휴식·치료, 휴대품·보관함, 수리·탈출 영역이 열린다. 화면이 낮으면 창 안에서 스크롤하며, 고정 HUD와 상단 X는 유지된다.

1. 탐색에서 재료와 보급품을 얻는다.
2. 안전지대에서 재료 묶음을 선택해 상자에 넣거나 꺼낸다.
3. 세척액1회분으로 선택한 묶음 전체를 세척한다.
4. 필요 없는 묶음은 폐기 → 확인으로 빈칸을 확보한다. 취소는 데이터를 바꾸지 않는다.
5. 휴식 시간을1~8시간 중 선택해 체력을 회복한다.6시간 이상이면 보너스,4시간 이상이면 오염 감소가 적용된다.
6. 의료 키트를 사용해 오염을 낮추고 질병을 치료한다. 실제 소모량과 질병 결과는 서버의 예상값으로 표시된다.
7. 세척한 재료가 모이면 수리·장착한다. 양쪽 저장소의 재료를 함께 사용한다.
8. 선택된4개 부품을 모두 수리한 뒤 **탈출하기**를 눌러 성공 결과를 본다.

| src/main/resources/static/css/safe-zone.css | 안전지대3열·재료 타일·경고·버튼 배치 |

| src/main/resources/static/css/result.css | 결과 색상·통계 카드 배치 |
| src/main/resources/static/js/app.mjs | 기존 공통 통신·최신 상태·종료 화면 전환·재시도 연결 |
| src/main/resources/static/dev/safe-zone.html | A 화면 없이 두 모듈을 확인하는 개발 페이지 |

HTML은 화면 구조, CSS는 모양, JavaScript는 버튼·API 연결을 담당한다. IntelliJ에서 같은 프로젝트로 편집하고 Spring Boot를 실행하면 된다. 별도 프론트 서버는 필요 없다.

## 화면 상태와 DB 변화

| 행동 | 명령·기존 API | DB 처리 |
|---|---|---|
| 재료 선택·휴식 시간 변경 | 로컬 상태만 변경 | 없음 |
| 상자에 넣기/꺼내기 | MOVE_ITEM → PATCH items/{batchId}/storage | 위치 변경, 필요하면 CLEAN 묶음 병합 |
| 세척 | CLEAN_ITEM → POST items/{batchId}/clean | 상태·시간·체력·세척액 갱신, 병합 대상 정리 |
| 폐기 확인 | DISCARD_ITEM → DELETE items/{batchId} | 묶음 삭제와 폐기 수량 통계 갱신 |
| 휴식 | REST → POST rests | 시간·체력·오염·질병 기한·다른 재료 만료 반영 |
| 치료 | TREAT → POST treatments | 키트·오염·질병·시간 갱신. 기한 실패 시 키트/질병은 예상값대로 유지 |
| 수리·장착 | REPAIR_PART → POST repairs/{partId} | CLEAN 재료 수량 감소/소진 묶음 삭제·수리 완료·시간 갱신 |
| 탈출 | ESCAPE → POST escape | 서버가 성공/실패 확정 |
| 최종 결과 읽기·창 닫기 | 서버 screen의 통계 렌더링/로컬 닫기 | 없음 |
| 결과의 새 게임 | 로컬 시작 화면 복귀 | 없음. 시작 화면에서 다시 눌러야 새 판 INSERT |

서버 변경 성공 후 GET screen으로 새 값을 받는다. 프론트가 먼저 재료를 없애거나 성공을 계산하지 않는다. batchId가 병합으로 사라지면 선택·폐기 확인을 해제하고 다른 묶음으로 자동 대체하지 않는다.

## 제한과 미리보기

- 체력·세척액·키트·재료 부족은 회색 버튼과 이유로 표시한다. 선택/정보 확인과 X는 사용할 수 있다.
- 서버 allowed=true이면서 projected.status=FAILED인 행동은 경고하되 실행할 수 있다.
- 치료가 기한에 도달하면 키트가 보존되고 질병이 남는 경우까지 projected에 따라 표시한다. 정상 치료 안내와 구분한다.
- pending 중에는 새 변경을 막고 기존 공통 다시 시도를 사용한다. 이미 성공한 행동은 같은 요청 번호로 확인하므로 중복 소모하지 않는다.
- 결과 화면에 성공/실패 원인, elapsedHours, 서버 날짜·시각, 완료 부품과 일반/방/열쇠 통계를 표시한다. 결과 열람만으로 DB 삭제나 순위 등록을 하지 않는다.

## 실행

IntelliJ에서 Spring Boot 재실행 → http://localhost:8080 → 새 게임 시작 → 안전지대.

독립 확인: http://localhost:8080/dev/safe-zone.html . 테스트 판 시작을 직접 누른다. 병원 탐색·6시간 휴식으로 실제 API 데이터를 준비할 수 있으며 임의 보상을 만들지 않는다.

## 검증 — 2026-10-27

- Java/MySQL115개, JavaScript55개 통과·건너뜀0, JAR 빌드 성공.
- 별도 서버18080·scrap_escape_test에서 실제 병원 탐색→휴식·치료→묶음 이동·세척·폐기 확인/취소→4개 수리→별도 탈출 성공 확인.
- 시간 초과와 질병 치료 기한 초과를 실제 서버에서 발생시켜 결과 원인 확인. 결과 재열기와 새 게임 시작 화면 복귀 시 생성 POST 없음 확인.
- 휴식은 서버에서 처리했지만 응답만 유실시킨 뒤, 같은 요청 번호로 재시도하여6시간이12시간으로 중복 증가하지 않음 확인.
- 선택 재료가 사라진 snapshot에서 폐기 확인·선택 해제, 키보드 Tab/Escape·포커스 복귀 확인.
-1280×720·1440×900·1920×1080에서 가득 찬4칸/16칸 상태의 가로 넘침·페이지 스크롤·HUD 겹침 없음 확인. 창 내부 세로 스크롤은 의도한 동작이다.
- 독립 개발 페이지의 생성 전 자동 POST 없음과 실제 시작/모듈 연결 확인. 콘솔 미처리 예외0.
- 코드 검토에서 지적된 치료 기한 안내를 수정하고, 키트 보존/질병 유지와 정상 치료 회귀 테스트 RED→GREEN 및 최종 브라우저 재검증을 수행했다.

수리 검증용 CLEAN 재료와 경계 기한은 **기록한 테스트 판에만 SQL로 준비**했다. 자연 탐색만으로 탈출하는 전체 난이도/밸런스는 별도 플레이 검증이 필요하다. 개인 scrap_escape DB는 변경하지 않았다. 최종 배경·아이콘은 여전히 임시이며 결과 별도 저장·순위표·외부 배포는 이번 범위가 아니다.

## 행동 완료·여러 묶음 이동·체력15

이제 휴식·치료·이동·세척·폐기·수리를 성공하면 창/정비 화면을 닫고 야영지로 돌아간다. 오류와 응답 미확정은 창을 유지한다. 탐색/방 보상과 최종 결과는 기존 확인 흐름이다.

재료를 한 번 누르면 선택, 다시 누르면 해제된다. 여러 묶음을 선택하고 이동하면 새 SE-17 API를 한 번 호출한다. 모두 들어갈 공간이 없으면 일부만 옮기지 않고 전체 취소한다. CLEAN은 최대6개씩 합쳐 담는 여유를 계산한다. 휴대품과 상자를 섞어 선택하면 같은 위치만 고르라는 이유를 표시한다. 세척·폐기는 한 묶음 선택 시만 가능하다.

세척된 재료는 인벤토리/상자/고정HUD에서 청록색 테두리와 ✓ 세척 완료로 구분한다. 새 판 체력은15/15, 기존 판은 남은 값을 유지하고 휴식 상한만15이다. 행동 비용은 유지했다. Java/MySQL122개·JS68개·실제 브라우저에서 자동 복귀·토글·3해상도·CLEAN 병합·공간 부족 전체 롤백·응답 유실 재시도·수리 후 복귀/탈출을 확인했다.

## 세척 보급·실패 결과 배치 — 2026-10-28

세척액 최대8·일반 탐색 획득80%로 변경했다. 초기1회분은 유지한다. 세척은1시간/액1회분을 쓰며 체력을 쓰지 않는다. 체력0에서도 유효한 미세척 묶음과 세척액이 있으면 가능하다.

최종 결과 창은 아래 공통 대화 영역을 숨겨21개 통계·새 게임을 스크롤 없이 표시한다. 응답 미확정의 재시도 수단은 유지하고 일반 행동 창의 메시지는 그대로다. MySQL124개·JS68개·실제 브라우저의 체력0 세척 및 시간/질병 실패 각각3해상도에서 footer높이0/내용스크롤0/새 게임 노출을 확인했다.


## 2026-10-28 추가 반영: HUD 통일·행동 창 유지·일괄 세척/폐기

모든 화면의 고정 생존 상태와 인벤토리는 안전지대의 크기·글자·패딩을 공유한다. 보관함에서 이동/세척/폐기, 정비에서 수리 완료 뒤에는 현재 창을 유지한다. 휴식/치료는 야영지로 복귀하며 게임 종료는 최종 결과가 우선한다. 오류·응답 미확정은 기존 창과 다시 시도 기능을 유지한다.

선택은 클릭 토글이며 여러 묶음 세척/폐기가 가능하다. 세척은 묶음 수만큼 액과 시간을 사용(묶음당1회분/1h/체력0)한다. 액이 부족하면 버튼 비활성·사유를 표시하고 서버도409 INSUFFICIENT_CLEANER로 전체 취소한다. 양쪽 저장소 혼합 선택 가능. 폐기는 전체 이름·수량 확인 후 한 요청으로 처리하고 취소는 변경 없음. 새 판/선택 변경/사라진 ID는 확인을 초기화한다. 휴식 정보에서 ‘체력 소모 0’만 생략하며 시간·실제 회복량은 유지한다.

추가 명령 CLEAN_ITEMS/DISCARD_ITEMS, 추가 API SE-18/19. docs/api에 최신 명세·OpenAPI·실제 응답 예시를 함께 제공한다.
